# Live voice: the real-phone checklist and the release checklist

Two checklists of [ADR 031](decisions/031-live-voice-in-rooms.md) (live voice in a room), written by C5, the step that measured and audited it (architecture §10 "Live voice", §12 "Live voice"). C5 measured decision 31's table and ran decision 26's drills **in a harness** — headless Chrome with a synthetic tone as each microphone, a container whose own link was slowed or cut — and audited every promise of the record on the Docker stack with the `voice` profile. A harness has no radio, no audio session, no loudspeaker and no lock screen, so what only a phone can answer is the first checklist; the second is for any operator who turns the voice on.

Neither checklist is run before the owner has read the sentences of ADR 031 decisions 14–17, the newcomer rule (decision 12) and variant A «Zolaq», and said yes (C5-O). Until then the ADR is "Proposed" and `ELIFBA_ROOMS_VOICE` stays off everywhere people play.

**⚑** marks a result that would change the contract: if it comes out as the step says, the ADR (and with it §12 and docs/frontend.md rule 15) changes first, and the code follows in a change of its own.

## 1. The real-phone checklist

For the owner: an iPhone (Safari) and an Android phone (Chrome), on the https try-out of §10 on Wi-Fi (part A), and on a public instance on mobile data (part B) — the try-out has a LAN address, which a phone on mobile data cannot reach. Write each result in its column; the owner's copy to fill in lives outside the repository. A result that misses its target is a finding: it goes to the next session as it stands, with what the phone said and showed.

### Setup, part A: the try-out on the LAN (Wi-Fi)

On the laptop, in a fresh clone of the branch under test (never the development folder: the stack reads the repository's own `.env`):

```bash
git clone <your clone> elifba-try-out && cd elifba-try-out
git switch feat/rooms-voice                     # main, once it is merged
ip=$(ipconfig getifaddr en0)                    # the laptop's LAN address (Linux: hostname -I)
scripts/docker-env.sh "$ip" https 8443
```

In `.env` set these four lines (the file already has the last three, empty or false), then start:

```dotenv
ELIFBA_ROOMS=true
COMPOSE_PROFILES=voice
ELIFBA_ROOMS_VOICE_IP=192.168.1.20
ELIFBA_ROOMS_VOICE=true
```

```bash
docker compose up -d --build --wait
docker compose cp proxy:/data/caddy/pki/authorities/local/root.crt elifba-try-out-ca.crt
```

- Allow UDP 7882 and TCP 7881 in the laptop's firewall (on macOS, accept the incoming connections Docker asks for).
- Install and trust `elifba-try-out-ca.crt` on both phones as the README's "Live voice on real phones" says, and on the laptop (macOS: open it in Keychain Access and set "Always Trust"). Remove it everywhere when the try-out is over.
- Register three made-up accounts at `https://<ip>:8443/register` as players — the host (the laptop's Chrome), the iPhone, the Android — with names you will recognise in a log. Without mail, each confirmation link is in the log: `docker compose logs app | tr -d '\r' | grep -oE 'https?://[^] ()<]+/email/verify/[^] ()<]+$' | tail -n 1`.
- The host opens a game on the laptop, then the room's big screen in a second window; the phones join with the code. The host turns the voice on in «Otağın idarəsi» → «Canlı səs». Another phone that films at 240 fps (slow motion) is the stopwatch of P2, P4 and P19.

### Setup, part B: a public instance (mobile data)

A throwaway VPS with a domain, set up as the README's "Run your own instance" says, with the same four lines and its public IPv4 as `ELIFBA_ROOMS_VOICE_IP` and the release checklist's "Before" B3–B6 done — or, after the release, the production host itself (decision 29: the production host is measured only after the release, in the release's own plan). The phones' Wi-Fi is off, except in P21 and P22.

### What is not built

- **TURN over TLS on 443** (decision 4, open question 51): a network that allows only 80 and 443 gets no voice, and the page says so; the game plays on. P22 and the players' reports say how often.
- **The voice container's hardening** (the audit's m9 and m10): it shares the default network and has a route out; it runs as root with a writable filesystem, Docker's default capabilities and no limits. `docker-compose.yml` sets none of it; a release that adds it starts at §10 — and a rule against its traffic out must still let the media reach the phones.
- **A Content-Security-Policy** (the audit's m14): no promise needs one; a strict one would break the pages as they are.
- **The half-open network's words** (decision 26, "As built (C5, measurements)"): built only if P18 or P21 shows it on a phone.
- **More than one voice server**: one per instance, `elifba.rooms.voice.max_rooms` (5) rooms with the voice on at once.
