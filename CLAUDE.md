# Elifba — notes for coding agents

Elifba is a Laravel 13 + Inertia 3 + React 19 app (the official React starter kit, PHP 8.4) where primary-school teachers in Azerbaijan run reading games — letters, syllables, words, sentences — on the classroom wall and drive them from their phone. Students have no accounts. The roadmap "Roles and parents" (R1–R7) adds a second role: a parent plays at home with their own children, without a class, and children who cannot read yet play picture and number games. R1 designed it (ADRs 010–013, the R-marked text of the architecture); a rule below that names R2–R6 holds from that step on. The roadmap "Adults' rooms" (B1–B7) adds an area of its own where account holders race each other at memory, logic and word games in a room, hidden behind a switch until launch. B1 designed it (ADRs 019–024, architecture §12); a rule below that names B2–B7 holds from that step on, and none of them loosens a rule of a class game, a home game or a child. The roadmap "Games first" (G1–G3) turns that area round: it is known as «Oyunlar», a game is chosen first and the room opens behind it. G1 designed it (ADR 026, architecture §12 "Games first", docs/frontend.md rule 15 "Games first"); a rule below that names G2 or G3 holds from that step on, and none of them loosens a rule of a room. P1 designed how a room game shows its players as rivals — a PK strip at the top (ADR 027, architecture §12 "Rivals face to face (P2)", docs/frontend.md rule 15 "Rivals face to face"); a rule below that names P2 holds from that step on. T1 designed taunts — a ready-made jibe a player throws a rival during a room game, for a point of their own (ADR 029, architecture §12 "Taunts (T2)", docs/frontend.md rule 15 "Taunts"); a rule below that names T2 holds from that step on. The roadmap "Live voice" (C1–C5) lets the players of a room talk while they play, through a voice server the instance hosts itself, behind a switch of its own. C1 designed it (ADR 031, architecture §10 "Live voice" and §12 "Live voice", docs/frontend.md rule 15 "Live voice"); a rule below that names C2–C5 holds from that step on, and none of them loosens a rule of a room, a class game, a home game or a child.

**Read first:** `docs/architecture.md` (the contract the code follows), `docs/glossary.md` (Azerbaijani terms and the English names used in code), `docs/frontend.md` (UI rules) and `docs/decisions/` (the hard-to-reverse choices). When the model changes, change the contract first, in the same change.

## Commands

- `composer ci:check` — the gate CI runs: `vp check` (oxlint + oxfmt), `tsc --noEmit`, `vp test` (Vitest: `resources/js/**/*.test.ts` against `tests/Fixtures/contract/`), Pint, PHPStan level 8 (Larastan), Pest. Run it before calling work done.
- `php artisan test --compact --filter=<name>` — the tests you touched.
- `composer test:pgsql` — the Pest suite on a throwaway `postgres:17` container (Docker), as the CI `pgsql` job runs it; arguments go through `scripts/test-pgsql.sh --filter=<name>`. A plain `php artisan test` is always in-memory SQLite.
- `vendor/bin/pint --dirty` and `npm run check:fix` — fix formatting.
- `php artisan wayfinder:generate --with-form` — regenerate typed routes after changing a route.
- `composer setup` once (it also writes the Reverb keys to `.env`), then `composer dev` (Vite, Reverb, logs, `artisan serve`); Herd serves `http://elifba.test`. `composer dev:lan` runs the same stack on the laptop's LAN IP so a real phone can open `/pult` (architecture §10).

## Rules

- **Domains.** Code lives in `app/Domain/{Language,Content,Classroom,Family,Play,Rankings}`, each with `Actions/`, `Models/`, `Enums/`, `Data/`, `Events/`, `Support/`, `Policies/` as needed. A domain may use the ones before it in that list, never the ones after: `Language → Content → Classroom → Family → Play → Rankings`; R3 built `Family` (a parent's children, `routes/family.php`). B2 adds `Rooms` at the end (`… → Rankings → Rooms`): nothing may use it, and it uses only `Language`, `Content` and `Rankings\Support\DenseRank` — never `Classroom`, `Family` or `Play`. The account is the starter kit's `App\Models\User` — the teacher until R2, then a teacher, a parent or both; every domain may reference it and `App\Enums\Role`. A3 built `Classroom` and the minimum of `Language` (`Alphabet`, `Az`, `AzCollator`) and `Content` (`Avatars`) it needs; A4 extends `Language` (letter names, confusables, `Syllabifier`, `Ordinal`) and builds the rest of `Content`; A6 builds `Play` (games, rounds, answers, the round contract, `RoundJudge`, `PointsRule`, `SchoolCalendar`, `Playable`, the `find` builder, the board endpoints in `routes/play.php`) and A6.2 the board UI; A7 adds pairing and guest boards; A9 builds `Rankings` (read-only: `ClassRanking`, `DenseRank`, `PeriodData` — the `?period=day|week&date=` query A10's podium reuses — and the rankings page in `routes/rankings.php`) with `Language\Support\DateLabel` and `Ordinal::label()`.
- **Only Actions write.** Controllers, commands and channel callbacks validate, call one action and shape the response. Validation lives in `*Data::rules()` and is reused by every entry point. The kit's own writes follow the same rule (`App\Actions\Fortify\*`, `App\Actions\Settings\UpdateLocale`; from R2 `App\Actions\Roles\{GrantRole,SwitchArea}`; ADR 017 `App\Actions\Settings\{UpdatePassword,LogOutOtherDevices}`).
- **Roles** (R2, ADR 010, architecture §1 "Accounts and roles"). Roles come from `spatie/laravel-permission`, roles only: never define a permission, never write a role name as a string — pass `App\Enums\Role`. A role opens an area and nothing else: every authenticated route sits in the teacher, parent, shared or account group (`role:teacher`, `role:parent`, `role:teacher|parent`, with `role.chosen`), and `tests/Feature/Auth/RoleAreasTest.php` fails for a route in none. From B2 there is a third role, `Role::Player`, and a fifth group (`role:player` with `rooms.enabled`) that holds every room route and nothing else; the shared group stays `role:teacher|parent`. Rows are still guarded by ownership (scoped binding and policies), which never ask for a role. Only `GrantRole` gives a role, with that role's agreement; a role is never removed. Registration creates an account with no role; `/start` is where a signed-in account is sent, never `/classes`.
- **A game is for a class or for one child** (R3, ADR 011). Play reads who a game is for only through `Play\Data\GamePlayers`; never add a code path that assumes a class, and never a third case: a room game is not a `game_sessions` row (**Rooms** below). In a home game the child is always the one at the board: no student id is read or stored. A parent's child and a teacher's student are never linked. Children have stars (`Rankings\Support\ChildStars`, derived) and never a ranking, a place, a podium, a share card or a list ordered by stars. Rows a teacher or a parent owns bind through `App\Models\Concerns\BelongsToOwner` (`whereOwner`, `isOwnedBy`). R4 built the parent pages (`children/{index,show}`, `components/children/*`, the home board and remote, docs/frontend.md rule 12): no ranking, place or podium reaches them, and `ChildPagesTest` checks their props for it.
- **Rooms** (B2–B7, ADRs 019–024, architecture §12). Adults' games are an area of their own behind `config('elifba.rooms.enabled')` (`ELIFBA_ROOMS`, off by default; read only through `App\Support\RoomsArea`): with it off every room route is a 404 and the player role is neither offered, granted nor listed. Nothing of rooms reaches a class, student, child, ranking, words, setup, board, remote, `/pult` or guest board page, the game catalog, `Content\Enums\Mechanic`, `content/levels.json` or `content/prompts.json` — `RoomsSwitchTest` and `RoomsApartTest` check it, and new routes with `{room}` or `{member}` go into the isolation test. The welcome page's section «Böyüklər üçün oyunlar» (`components/welcome/rooms-section.tsx`) and `/privacy`'s «Böyüklərin oyunları» are drawn only from a prop their controllers send while the switch is on (B7, G3); `RoomsWordingTest` reads every room text, the READMEs' «Böyüklər üçün oyunlar» / "Games for adults" included. Every player is an account shown under `users.name`; no room table holds a name or anything a person typed, and a room never takes a student or a child. A room code comes only from `Rooms\Support\RoomCode` (its own code space, `/oyun` from G2, `/otaq` before) and admits a signed-in, confirmed account with the player role into that one room — nothing else. From B3: each player's device posts only its own answer and only `RecordRoomAnswer` writes it (one per player per round, idempotent by `event_id`); the server alone judges (`RoomJudge`), scores (`RoomPointsRule`) and keeps the clock (`RoomClock`, Unix milliseconds) — never mirror them in TypeScript, never send a solution or a right-or-wrong before the round is closed, never trust a device's clock. A round waits only for a present player who answered it or whose room page has read the state since the round before closed (`RoomWaits`, ADR 021 as amended 2026-11-18): the read is `room_players.seen_ms`, written only by `RecordRoomRead` and never for the big screen, and a read never closes a round. The round, its phase and the ranking are derived (`RoomTimetable`, `RoomRanking`), never stored, and nothing is queued or scheduled for a round. The room channel (`room.{id}`, the `web` guard only) carries `room.changed` `{v, revision}` and nothing else; a room page sends and hears no client event. A player's name is never in a log, an exception, a broadcast or a URL; devices get `room_players.id`, never an account id or an address. No age, date of birth, age group, nickname, chat or free text; no total, rating or profile across rooms; no interface text that promises a benefit to memory, mind or health. A game's motion, its final and its sound follow ADR 025 (the sound set: ADR 028): a page animates only a moment of the state it saw begin (`roomMoment()`), nothing moves or sounds differently for a right or a wrong answer before the reveal, every animation stands still under `prefers-reduced-motion`, confetti belongs to the final alone, and the screen is the room's speaker while a phone plays only its own quiet cues (`roomCues()`, once per moment the page saw begin) — and in a room without a screen every phone plays the room's cues too, never the winner's cheer (ADR 028 as amended 2026-11-19: the state's `room.screen`, derived by `RoomScreen` from `rooms.screen_seen_ms`, which only `RecordScreenRead` writes from the shown screen's reads; `carriesRoom()`) — each device with a mute of its own in `localStorage`; room sounds are the files of `content/rooms/sounds.json`, made only by `scripts/room-sounds/make.py` (CC0 recordings pinned by SHA-256, and our synthesis), the countdown and the clock placed on the server's clock and stopped with their moment, and the screen gets only its own speaker's files, a phone its own and the room's. One voice enters a room (ADR 030): at the final the screen alone cheers the first place after the fanfare, as a home board ends a game — the first name (the built-in name list's clip, matched only by `NameVoices`; at most three who share the place) and then the board's «Əla oynadın!» / «Əla oynadınız!» (props `finish`), never a new phrase, a new clip or speech; a name's clip comes only from `GET /rooms/{room}/members/{member}/voice` (ids, `can:screen`, `no-store`); the clips are fetched once the page heard the final begin and its sound is on, and never fetched or played by a phone. Room content lives in `content/rooms/` and room mechanics in `Content\Enums\RoomMechanic`; a room page draws a letter or a word as the server cased it — no `uppercase` or `capitalize` class and no `toUpperCase()`, which lose «ı» and «İ» outside an Azerbaijani locale — and a player types nothing (an anagram is tapped tiles, B6); the word list is our own (MIT), and another source enters only under a license `Content\Enums\License` allows. From G2 (ADR 026): the host's not-yet-started choice — game, difficulty, rounds — lives in `rooms.setup_*` and reaches every device as the state's `setup`; only `OpenRoom` and `ChooseRoomGame` write it, `StartRoomGame` reads it and takes no body, and only the host changes it or starts, from the room page or the screen (`RoomPolicy::start`) — never a client event, never a page's own memory; the entrance is `/oyun` and `/otaq` only redirects to it; a new room's difficulty and rounds are derived (`RoomDefaults`), never stored on the account. From G3: the interface says «Oyunlar», «Keçmiş oyunlar», «Oyun kodu», «Oyuna qoşul» and «aparıcı» (code names stay `Rooms`, `rooms.*`, `{room}`), and «otaq» only where the room itself must be named — «Otağın idarəsi», «Otağı bağla», «Otağın sıralaması», a closed room, the player role's sentence, `/privacy` (ADR 026 decision 2: «Otağı bağla» is not «Oyunu bitir»; `RoomsWordingTest` checks it); the start screen on the phone and the screen draws the state's choice with the same parts (`components/rooms/game-settings.tsx`: `GamePicker`, `DifficultySegments`, `RoundStepButtons`, `GameSettings`), a tap posts and the page waits for the state (`useRoomChoice()`), and a player's phone shows it read-only; the camera of the code field (`RoomScanner`) reads a QR on the device, accepts only this app's `/oyun/{code}` (`scannedCode()`) and sends no picture anywhere; no room file imports the children's catalog. From P2 (ADR 027): a live game shows its rivals in one strip (`RivalryStrip`) above the round on the phone and under the screen's top bar — a player against the leader, or the runner-up when leading; two players face to face; on the screen the first two — picked by `rivalPair()` from the state's ranking in the server's order and never re-sorted (no state field of its own); it stands still until a reveal the page saw begin, and an overtake is only a change between two pairs the page drew (`overtakeOf()`); its sides are sky and orange, never right's, wrong's or the lamp's colour and never a person's; its three emoji (⚡ 👑 🔥) are Fluent files named by `content/rooms/rivalry.json` and reach a page as the prop `rivalry` — of the state, never of a person. From T2 (ADR 029): a player may throw a present rival a taunt — a key of `content/rooms/taunts.json`, its emoji a Fluent file and its phrase `rooms.taunts.say.{key}`, never typed text and never a sound — and only `ThrowRoomTaunt` writes it (idempotent by `event_id`, under the room row's lock); it costs the thrower `RoomPointsRule::TAUNT_COST` (1), the target nothing; the balance (answers over closed rounds less every taunt thrown in the game) and the cost are derived, never stored, a throw needs a balance of 1 and nothing goes below 0; a taunt counts in the ranking from the first close after it, so the ranking and the strip still move only at a close; it never closes a round, counts as an answer or as a read; it reaches only its target's phone and the screen, for `rooms.taunts.show_ms`, through the state (`v: 3`) and never the channel; the host's switch is `rooms.taunts` (`SetRoomTaunts`); who taunted whom is shown nowhere after the game and the target is emptied after a day. From C2–C5 (ADR 031, architecture §12 "Live voice"): people's own live voice — not the screen's one voice of ADR 030 — is behind its own switch, `config('elifba.rooms.voice.enabled')` (`ELIFBA_ROOMS_VOICE`, off by default; read only through `RoomsArea::voice()`) — with it off every voice route is a 404, the state's `voice` is null and no page, prop or text names it. A voice travels only through the instance's own voice server (the Compose service `voice`): never a cloud service, a public STUN or TURN server, or phone to phone — the server is given `node_ip` with `use_external_ip: false` and its own `stun_servers`, and the page connects with `iceServers: []`. A room's voice is off until its host turns it on; the host's choice, an admission and a mute are facts in rows (`rooms.voice_at`, `rooms.voice_epoch`, `room_players.voice_admitted_at`, `room_players.voice_muted_at`) that only `SetRoomVoice`, `SetRoomPlayerVoice` and the actions that end a presence write, and that reach every device as the state's `voice` and `players[].voice` — never a client event; who is in the voice, whose microphone is open and who speaks are never stored, logged or put in the state. Only `JoinRoomVoice` issues a ticket: to the host or a present, admitted player of an open room whose voice is on, after the account's stamped agreement (`users.voice_agreed_at`; the player role's sentence is never reworded for it), naming the player by `room_players.id` and nothing else, with every permission written out and never `roomCreate`, `roomAdmin`, `hidden` or `recorder`; an account that joins after the voice is on waits until the host admits it, and the screen never gets a ticket, plays a voice or captures one. Only `RoomVoiceServer` talks to the voice server — after the commit and after the signal, never under the room's lock, never from an answer, a read or the state — so a voice server that is down delays no round; a removal, the voice going off and a close raise the epoch, and `SweepRoomVoices` makes the voice server match the facts. Nothing turns a microphone on but its owner's tap; nothing is recorded, transcribed or processed on the server (no egress, ingress or agent service, no webhook); the room channel still carries only `room.changed`; `livekit-client` is imported only by `resources/js/rooms/voice.ts`; a class game, a home game, a board, a student and a child never get voice, and the board's prerecorded voice (ADR 015, `elifba.voice.*`) is another thing; new voice routes go into the isolation test; a voice text never promises a benefit and says «Canlı səs», while the cues are «Oyun səsləri».
- **Remembered login** (ADR 017, architecture §7 "Remembered login"). «Məni xatırla» lasts `auth.guards.web.remember` (`AUTH_REMEMBER_DURATION`, 30 days); sessions stay `SESSION_LIFETIME`. Every way that changes a credential calls `LogOutOtherDevices` (rotates the remember token, deletes the account's other `sessions` rows) and then `RememberedLogin::keepThisDevice()` with the token read before; never mint a recaller from a cookie that is not this account's live one. «Çıxış» is `Auth\LogoutController` (this device only), not Fortify's. Google sign-in follows the page's box (`google.intent.remember`).
- **Statuses** change only through `TransitionGameSession` (`GameSessionStatus::allowedTransitions()`); derived things (the current round, rankings, places) are never stored.
- **Facts are events after commit** (`GameSessionTransitioned`, `RoundSolved`); listeners never run inside the writing transaction.
- **The board is the only writer of results** of a class or home game (a room: **Rooms** below). The phone never posts hits; it sends client events. Every result goes through `RecordBoardEvents`, idempotent by `event_id` and fenced by `board_epoch`.
- **Two board modes, one protocol.** A teacher board uses the teacher's session; a guest board uses its bearer, which reaches only the game it shows — never classes, rankings or other games. Pairing codes come only from `PairingCode` and never authorize anything (a room code is another thing: **Rooms** below).
- **One judge, one points rule.** `RoundJudge` (mirrored by `engine.ts` against the shared fixtures) and `PointsRule` (PHP only). The round contract changes in the PHP DTOs, the zod schemas in `contract.ts` and the fixtures together; TypeScript types are inferred from the schemas, never written by hand.
- **Content is data.** Never hard-code words, letters, prompts or theme looks in PHP or TypeScript; add them to `content/` and run the validator. Text is cased, syllabified and ordinal-suffixed on the server (`Language`), never in TypeScript.
- **Picture and number games** (R5, R6, ADR 012). What an item is belongs to the unit (`picture`, `number`), not to a new mechanic: `find` and `pop` play them, and `count` is the one new mechanic. A pack lists its `units`, and a level plays only with a pack that lists its unit. Learned letters, the letter case and own words apply only where `Unit::reads()`. Prompts never attach a suffix to `«{x}»` («pişik» hansıdır?). No picture holds a digit or text; digits come from the level's range. The board says prompts and praise in prerecorded clips (V1, ADR 015, architecture §3 "Voice"): files under `content/assets/voice/` through `prompt.audio` (`PromptVoice`; a teacher word's stays null), made only by `php artisan content:voice` from built-in content, never speech synthesised at runtime, never an item read for the child, never a teacher word voiced, and never a student's or child's name sent to a speech provider. From V2 (ADR 016) a first name is said only from the built-in name list (`content/names.json`; clips in `content/voice-names/`, made by `content:voice` without reading a row; matched by `Content\Support\NameVoices`), and a board gets a name's clip only through `GET /games/{game}/players/{player}/voice` (a room's screen through its own route, **Rooms** above): never a name or a name's hash in a URL, never a public file.
- **Teacher words** (ADR 007, ADR 009, architecture §3) are rows, not files: `custom_words` (a teacher's own word, played in every pack, no picture) and `hidden_words` (a built-in word one teacher hid), written by `AddCustomWord`, `UpdateCustomWord`, `DeleteCustomWord`, `HideWord`, `ShowWord`. Play reads a pack only through `Content\Support\TeacherPacks` wherever it builds or checks rounds (setup options, `GameSetupData::rules()`, `StartGame` and the builders, which take the pack as an argument). The one exception is the welcome page's `SampleRounds`, which has no teacher and takes a built-in pack. `ContentRepository` reads only the files. The word rules live once, in `Content\Support\WordRules`, used by `ContentValidator` and `CustomWordData`. Teacher words never play in `build_word`. Teachers manage them on `words/index` (`routes/words.php`); `{word}` is a ULID, and hiding or showing sends the word in the body.
- **Children's privacy.** A student is a display name and an avatar — the name as the teacher writes it, surname and patronymic included (ADR 018; never an added initial, the share card shows the first name only) — and a parent's child is a first name and an avatar (R3: a first name, an avatar, the order and the learned letters; at most `elifba.children.max` per parent; no age or date of birth, ADR 013). Do not add fields about children. Never put a student's or a child's name in a log, an exception, a broadcast or a URL, nor a teacher word (it may be a child's name) in a log, an exception or a URL. New routes with `{class}`, `{student}`, `{game}`, `{word}` or `{child}` go into the isolation test. Nothing on the share card but architecture §6's list. Each role has its own agreement sentence (architecture §7 "Agreements"); do not merge them.
- **No third-party requests** from pages: no CDNs, external fonts, analytics or trackers. Fonts are committed in `resources/fonts/` and loaded with the `local()` provider in `vite.config.ts`.
- **Assets** enter only with an entry in `content/credits.json` and an allowed license; Fluent Emoji files stay in `content/assets/fluent/` and never on the share card; own art follows ADR 014's style guide; state symbols follow architecture §8.
- **Two languages.** Every interface string goes into `lang/az.json` (the base) and `lang/en.json`; `tests/Unit/TranslationsTest.php` fails on a missing or extra key, an empty string or different `:placeholders`. Keys are dotted (`settings.profile.title`); the only sentence keys are the framework's own (mail notifications, Fortify messages). React reads them with `useTranslation()`; layout props, breadcrumbs and nav items carry keys, and the component that renders them translates. Framework messages are `lang/{az,en}/{auth,pagination,passwords,validation}.php` and must keep the same keys. Content stays Azerbaijani in every locale.
- **Locale** comes from `SetLocale`: `users.locale` → the session's choice → `APP_LOCALE` (`az`); never `Accept-Language`. The switch is `PUT /locale` (`LocaleController` → `UpdateLocale`). Locales are listed in `config/elifba.php`.
- **Config** for Elifba's own values is `config/elifba.php` (`timezone` Asia/Baku, `locales`, `retention_days`, `pairing_code_ttl_minutes`, `guest_board_hours`, `abandon_after_hours`, `rounds`, `custom_words.*`, `operator.*`, `source_url`; R3: `children.max`; V1: `voice.*`, the key only `content:voice` reads; B2, B3: `rooms.*`; C3: `rooms.voice.*`, the live voice's, which is not `voice.*`); read it with `config('elifba.*')`, never `env()` outside `config/`.
- **No queue.** `QUEUE_CONNECTION=sync` everywhere; broadcasts are `ShouldBroadcastNow`. `composer dev` runs no queue worker.
- **Database portability.** Query builder and Eloquent only; no engine-specific SQL; Baku dates come from `SchoolCalendar`; names are sorted in PHP (`AzCollator`). Tests must pass on SQLite (the `ci` job) and PostgreSQL 17 (the `pgsql` job).
- **PHPStan level 8** covers the kit's code too. Fix the code; never lower the level, add a baseline or `@phpstan-ignore`. Use `#[CurrentUser] User $user` in controllers instead of a nullable `$request->user()`.
- **Tests** use Pest (`tests/Feature`, `tests/Unit`; both boot the app, only Feature refreshes the database). Fake time with `travelTo` around midnight and Monday boundaries; never call a real Reverb server in a test: tests run the `reverb` broadcaster with test keys and `tests/Support/FakeReverb` (`$this->reverb->sent`, `->down()`) in place of its HTTP client; or fake the event. Nor a voice server (C3): `Rooms::voiceOn()` turns the live voice on with `Config::set` and fakes the server's Twirp calls with `tests/Support/FakeVoiceServer` (`->sent`, `->joins()`, `->down()`), shaped from LiveKit's real answers; `Tests\TestCase` leaves the voice off with no server named.
- **Commits**: only when asked. Conventional subjects (`feat:`, `fix:`, `docs:`…).
